# 07: 목록: 정렬과 페이지 이동

**What to build:** 방문자가 `/`에서 최신 공지부터 10개씩 보고, 페이지 번호로 이동하며, 주소의 `?page`로 같은 페이지를 다시 열 수 있다. 상세에서 "목록으로"를 누르면 보던 페이지로 돌아간다.

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] 목록 항목은 `{id,title,createdAt,updatedAt}`이고 작성일시 내림차순, 같으면 id 내림차순이다. 주입된 시계로 같은 작성일시 공지를 만들어 검증한다
- [ ] 공지를 수정해도 목록 순서가 바뀌지 않는다(수정 기능 전이라면 `updatedAt`이 정렬에 쓰이지 않음을 검증)
- [ ] `size`는 10으로 고정되고 클라이언트의 `size`·`sort` 파라미터는 무시된다
- [ ] 범위 밖 페이지 요청은 빈 `content`와 올바른 `totalPages`를 돌려준다
- [ ] 프론트 목록 항목은 제목과 작성일(`yyyy.MM.dd`, Asia/Seoul)을 보여주고 상세로 연결된다
- [ ] 화면 `?page`는 1부터 세고 API에는 1을 뺀 값을 보낸다
- [ ] `?page`가 숫자가 아니거나 1보다 작으면 `?page=1`로 바뀐다
- [ ] 전체 페이지 수보다 크면 "이 페이지에는 공지가 없습니다"와 1페이지 링크가 보인다
- [ ] shadcn Pagination: 이전, 현재 페이지 중심 최대 5개 번호, 다음. 현재 페이지 강조, 첫·마지막 페이지에서 이전·다음 비활성화, 1페이지뿐이면 숨김
- [ ] 상세의 "목록으로"가 들어온 페이지로 돌아간다
- [ ] 위 프론트 동작은 MSW 테스트로 검증한다
